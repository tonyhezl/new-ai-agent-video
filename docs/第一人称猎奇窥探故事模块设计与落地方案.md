# 第一人称（POV）猎奇窥探故事模块设计与落地方案

## 1. 功能结论

POV 猎奇故事已经作为独立模块设计和实现，不进入普通“剧本 -> 场次 -> 分镜 -> 首尾帧 -> 视频”链路。

新链路为：

```text
AI 生成 POV 故事、故事资产和镜头绑定
    -> 生成故事级资产图
    -> 为每个发声角色配置音色并生成参考音频
    -> 镜头携带资产参考图和角色参考音频直接生成视频
    -> FFmpeg 顺序合成完整视频
```

两个原则：

- 生成故事资产图片，不生成镜头首帧、尾帧或普通镜头图。
- 角色声音由故事级参考音频锁定，镜头视频任务明确传递“角色 N -> 图片 N -> 音频 N”。

## 2. 模块隔离边界

POV 业务只读写以下专属表：

- `afv_pov_story`
- `afv_pov_shot`
- `afv_pov_asset`
- `afv_pov_asset_item`
- `afv_pov_shot_asset`
- `afv_pov_shot_speaker`

POV 只复用底层生成基础设施：

- 图片、视频、音频任务队列与消费者
- AI 模型配置和模型能力校验
- 媒体存储
- FFmpeg

POV 不读写普通业务的 `afv_asset`、`afv_asset_item`、Storyboard、SceneState 等数据，也不调用普通剧本的提示词编译服务。角色音色快照保存在 `afv_pov_asset.voice_config`，不会修改普通资产的 `properties.voiceConfig`。

通用的 `afv_image_task`、`afv_video_task` 和 `afv_audio_task` 仍作为底层任务表使用，任务通过 `category=POV_ASSET/POV_DIRECT_VIDEO` 标识来源；生成结果只回写 POV 表。

## 3. 故事资产模型

每个故事有独立资产包。资产是否需要创建由故事语义决定，不绑定老宅、教室或特定题材。

| 资产角色 | 用途 | 示例 |
|---|---|---|
| `SCENE` | 锁定重复空间结构 | 电梯、老宅、地下通道 |
| `KEY_PROP` | 锁定关键物体身份 | 日记、录像机、黑玉镯 |
| `POV_CHARACTER` | 锁定主角可见部分和声音 | 手套、袖口、手持设备、旁白音色 |
| `NPC_ENTITY` | 锁定可见人物或异常实体 | 管理员、镜中人 |
| `VEHICLE_BUILDING` | 锁定载具或建筑 | 潜水器、旧别墅 |
| `STYLE_BOARD` | 剧情必须的特殊成像语言 | 特定夜视界面、旧 DV 画质 |

每个资产至少包含一个 `initial` 子项。只有剧情真实改变资产状态时才增加 `variant`：

```text
door:initial(closed)
    -> door:opened
    -> door:broken
```

变体通过 `based_on_item_id` 依赖主图。批量生成资产时先并行提交所有无依赖初始图；主图完成后，轮询服务自动提交其状态变体。这样既保证外观继承，也保持跨资产并行性能。

资产图片只描述稳定身份、外观、结构和状态，不描述某个镜头的临时动作与构图。

## 4. 角色参考音频

每个可发声角色具有故事内稳定的 `characterNo`。页面可以对每个角色独立完成：

- 设置基础音色 ID、名称、语速、音高、情绪和自定义音色 ID。
- 编辑参考音频样本文本。
- 生成、试听和重新生成参考音频。
- 传入现有参考音频 URL 进行替换。

音色配置与参考音频的唯一真值为：

```text
afv_pov_asset.voice_config
afv_pov_asset.reference_audio_url
```

参考音频是角色级资产，不是镜头配音。同一角色的所有镜头复用同一条参考音频，避免逐镜 TTS 导致音色漂移，也避免视频原生对白与后置 TTS 重复叠加。

## 5. AI 输出合同

`pov_story_architect` 必须一次输出：

- 故事正文。
- `assets[].items[]` 故事资产与状态变体。
- 角色的 `characterNo/voiceRequired/voiceDescription/voiceSampleText`。
- `shots[].videoDescription/cameraMovement`。
- `shots[].assetRefs[]`。
- `shots[].dialogues[]`。

简化示例：

```json
{
  "assets": [
    {
      "assetKey": "caretaker",
      "assetRole": "NPC_ENTITY",
      "name": "管理员",
      "characterNo": 2,
      "voiceRequired": true,
      "voiceDescription": "年长男性，语速缓慢，冷淡克制",
      "voiceSampleText": "这里从来没有地下室。",
      "items": [
        {
          "itemKey": "initial",
          "itemType": "initial",
          "imagePrompt": "管理员角色身份设定图……"
        }
      ]
    }
  ],
  "shots": [
    {
      "shotOrder": 3,
      "videoDescription": "第一人称视角缓慢抬头，管理员从门边走进光束后停下",
      "cameraMovement": "SLOW_TILT_UP",
      "assetRefs": [
        {"assetKey": "basement", "itemKey": "initial", "referenceOrder": 1, "required": true},
        {"assetKey": "caretaker", "itemKey": "initial", "referenceOrder": 2, "required": true}
      ],
      "dialogues": [
        {"characterNo": 2, "dialogueText": "这里从来没有地下室。", "delivery": "冷淡，停顿明显", "sortOrder": 1}
      ]
    }
  ]
}
```

## 6. 镜头直接生视频

服务端根据最终入选 URL 顺序编译提示词，不信任 LLM 直接编写的“图片 N”：

```text
参考图片1是地下室（状态：初始状态），镜头中必须保持一致；
参考图片2是管理员（状态：常态），镜头中必须保持一致；
角色2是参考图片2中的管理员，角色2的声音严格参考音频1；
本镜头由角色2说：“这里从来没有地下室。”
未列为发声者的角色保持沉默，禁止交换角色声音或台词。
```

实际视频任务固定为：

```text
generateMode = text2video
firstFrameImageUrl = null
lastFrameImageUrl = null
referenceImageUrls = 镜头绑定的已确认 POV 资产图
referenceAudioUrls = 镜头实际发声角色的参考音频
generateAudio = 镜头是否有角色发声
```

DashScope 使用结构化声音映射：

```json
[
  {"imageUrl": "角色参考图 URL", "audioUrl": "该角色参考音频 URL"}
]
```

其他平台使用与提示词编号一致的有序音频 URL 数组，避免不支持结构化对象的适配器把对象误当 URL。

提交前执行严格门禁：

- 必需资产没有完成生图时拒绝提交。
- 发声角色没有参考音频时拒绝提交。
- 发声角色未绑定角色参考图时拒绝提交。
- 视频模型不支持参考图、参考音频或输入数量超限时拒绝提交。
- 不调用通用静默裁剪，防止裁剪后提示词编号与实际 URL 错位。

批量生成先完成所有镜头的预检，再提交任务，避免前几个镜头已提交、后续镜头才因缺资产失败。

## 7. 数据表

迁移文件：

```text
V1.0.8.0.1__pov_story_tables.sql
V1.0.8.0.2__pov_shot_media_task_id.sql
V1.0.8.0.3__pov_assets_direct_video.sql
V1.0.8.0.4__generalize_audio_task_source.sql
```

V2 新增表职责：

| 表 | 职责 |
|---|---|
| `afv_pov_asset` | 故事资产、角色编号、音色快照、参考音频状态 |
| `afv_pov_asset_item` | 初始资产图、状态变体、图片任务状态与依赖 |
| `afv_pov_shot_asset` | 镜头实际使用的资产子项和参考顺序 |
| `afv_pov_shot_speaker` | 镜头台词、发声角色和发声顺序 |

`afv_pov_shot` 新增独立的 `video_task_id/audio_task_id` 与 `video_status/audio_status`。历史 `media_task_id/media_task_type` 保留兼容但新链路不再写入，避免视频任务和音频任务互相覆盖。

通用 `afv_audio_task` 允许 `project_id/storyboard_id/storyboard_episode_id/storyboard_item_id` 为空，并将 `dialogue_type` 扩展为 `VARCHAR(32)`。普通分镜任务继续写入原关联字段；独立 POV 参考音频使用 `POV_REFERENCE` 标识来源，避免伪造普通分镜关联。

## 8. 前后端入口

后端位于：

```text
controller/pov
entity/pov
mapper/pov
service/pov
resources/prompts/agents/pov-*.system.md
```

主要接口：

```text
GET  /api/pov/stories/{storyId}/assets
POST /api/pov/stories/{storyId}/assets/generate-all
POST /api/pov/stories/{storyId}/assets/items/{itemId}/generate-image
PUT  /api/pov/stories/{storyId}/assets/{assetId}/voice
POST /api/pov/stories/{storyId}/assets/{assetId}/generate-reference-audio
POST /api/pov/stories/{storyId}/shots/{shotId}/generate-video
POST /api/pov/stories/{storyId}/generate-all
POST /api/pov/stories/{storyId}/compose
```

前端 `/pov-stories/[id]` 分为：

1. 故事资产与状态变体。
2. 每个角色独立的音色和参考音频。
3. 镜头参考图片顺序、角色声音映射和直接生视频。
4. 完整视频合成。

页面不再展示或提交“批量生成图片+配音”“单镜重新生图”“镜头首尾帧”。

## 9. 合成兼容

新生产路径要求所有镜头都有 `video_url` 才能合成，不再把镜头图片制作成运镜片段。

合成时优先保留视频模型生成的原生音轨。只有历史视频没有音轨且旧数据存在 `audio_url` 时，才使用旧独立配音；因此不会同时播放原生角色对白和后置 TTS。

## 10. 验收清单

1. 新建 POV 故事后，普通资产、剧本分镜和场景状态表没有新增或修改记录。
2. 故事详情能看到资产及状态变体；变体在主图完成后自动开始生成。
3. 每个发声角色可以独立配置、生成和试听参考音频。
4. 缺资产图或缺角色音频时，直接生视频按钮返回明确错误。
5. `afv_video_task.generate_mode` 为 `text2video`，首尾帧 URL 均为空。
6. `reference_image_urls` 顺序与页面“图片 N”一致。
7. DashScope 的角色图与音频使用结构化映射，其他平台的音频顺序与提示词一致。
8. 镜头之间同一场景、道具和角色保持故事资产身份一致。
9. 视频自带角色声音时，最终合成没有重复对白。
10. 普通“剧本到视频”页面和服务行为无变化。
